# Runtime UI kit integration

Implemented 13 November 2026 from the accepted [UI kit](ui-kit.md), [Field Kit reference](../../art/ui/kit/v1/responsive.html) and [UI sprites](../../art/ui/sprites/v1/README.md).

## Shared presentation

[src/styles/_ui-kit.scss](../../src/styles/_ui-kit.scss) owns the cream/navy/steel/coral palette, local display/body font stacks, angled buttons, selected-tab coral caps, native input/dropdown surfaces, continuous progress tracks, inset wells, reinforced dialog shells and rotated title plates. [src/styles.scss](../../src/styles.scss) loads it once. Controls, typography and resets are scoped to explicit `.sw-ui` surfaces and the CDK overlay container. The game overlay, notifications and loading screens opt in; the renderer host and development-only Babylon Inspector do not. Do not scope the theme to `app-root` or `body`: the Inspector mounts inside the renderer under that root. `.sw-ui` also enables the theme for test fixtures or standalone previews. Component styles own their layout and state-specific presentation.

Dialog bodies scroll inside fixed frames without stretching artwork. Separate SVG edge tiles and corner pieces preserve their original silhouettes and inner corner joins. The navy fill is inset behind them; transparent exterior cuts expose the game/backdrop. Shells share a protected body inset: 20 px inside the frame's 20 px border, with a 52 px lower reservation (60 px on very short windows). `.sw-scroll-region` adds 8 px around its contents for control shadows and focus outlines, and keeps its native scrollbar inside that protected body. Controls and Graphics normally retain fixed headers/actions while their content scrolls. Compact Controls uses stacked binding rows.

Footer button pairs use `.sw-dialog-actions`. Their shells reserve a 52 px lower inset outside the scrolling region, while action rows use matching 16 px left/right insets and place their buttons at either end. This keeps the right action close to the edge while clearing the larger lower-right reinforcement. Keep this shared spacing instead of overriding it with component footer padding. At window heights up to 420 px, the lower reservation increases to 60 px, while the inner content and actions can scroll together. Labels wrap at word boundaries within their buttons, preserving left/right controller navigation between the paired actions. Save and unfinished-work confirmations use the same treatment.

The [footer comparison captures](../../art/ui/kit/v1/previews/footer-spacing/README.md) show this spacing in a wide dialog and a 320×240 window.

On short windows, the main menu lays out settings, game actions and credits in separate flow regions. Its actions scroll when needed so Save/Load cannot cover New Game or Resume after Retry.

The Field Kit uses two work columns: inventory and crafting, with more width given to crafting. Handcrafting appears initially; owning a MiniFab replaces it with the MiniFab controls in the same pane. Dismantling the device returns to handcrafting. Existing restored handcraft jobs remain visible and cancellable under MiniFab recovery. Below 640 px of inner width, Inventory and Crafting become focused work areas; switching between them retains selections and does not cancel jobs. At window heights up to 480 px, the header, tabs and body scroll together inside the frame so the header cannot consume all available content space. Main section changes and closing still use the existing unfinished-work confirmation. Limits remain configurable in [variables.scss](../../src/variables.scss).

Research gives the graph the main workspace, with selected technology details and the research queue in a narrow right sidebar. Guidance is available under Research help. The tree heading and tools stay compact; queue growth cannot reduce the graph's height. Below 700 px of pane width, details and queue stack below the graph. Short windows preserve a useful graph height inside the protected scrolling body. The [updated research capture](../../art/ui/kit/v1/previews/dialog-layout/research-desktop.png) shows a 775×439 px graph viewport at 1234×898.

The crafting crank scales from 152–224 px with its pane and uses 176 px in compact layouts, with proportional artwork. Its stationary shadow wrapper clips the transparent rotating square, so turning the arm cannot change scrollable bounds. The crafting pane suppresses horizontal scrolling. Native controls retain a minimum 44 px target; the taller standalone proof remains a visual construction reference.

## Runtime artwork and preparation

Run from the repository root:

```powershell
node tools/art/prepare-ui-kit.ts
```

The [preparer](../../tools/art/prepare-ui-kit.ts) copies 26 SVG pieces into [public/assets/ui/kit/v1/](../../public/assets/ui/kit/v1/) and 31 transparent 128 px PNGs into [public/assets/ui/items/](../../public/assets/ui/items/). The total is 671,840 bytes. [runtime.json](../../art/ui/kit/v1/runtime.json) records every source, target, size and SHA-256 checksum. Unchanged copies are retained. The normal build/development entry points run this preparation automatically.

Large generated originals, concept screens, atlas and other reference exports stay under `art/`. The game loads individual sprite derivatives through [ItemSprite](../../src/app/shared/item-sprite/item-sprite.ts), using `NgOptimizedImage` with fixed intrinsic dimensions and proportional CSS sizing. [RecipePreview](../../src/app/features/game/recipe-preview/recipe-preview.ts) reads the real recipe data and does not issue gameplay commands or modify content definitions.

Production checks also verified loaded images and horizontal overflow, with Field Kit frames contained at 1440×900, 900×760, 390×844, 320×568 and 1280×480. Small and short windows scroll inside their frames.

The loading reference was captured with JavaScript disabled. Its AXE audit uses the bootstrap with application scripts withheld, allowing the audit's own timers to run. The development-only Babylon Inspector retains its SDK theme, and its separate Close Inspector control uses native button styling. The game's Inspector launcher remains part of the themed HUD.

Detailed diagnostics remain in the ignored [local UI review](../reports/ui-kit-2026-11-13/). They use temporary browser profiles and an existing earned checkpoint, are manually invoked, and are not CI gameplay routes.

The [dialog layout references](../../art/ui/kit/v1/previews/dialog-layout/README.md) record the subsequent two-column crafting and full dialog overlap audit from 16–17 November 2026. The [validation record](../../art/ui/kit/v1/previews/dialog-layout/validation.json) records 140 passing focused tests, the browser checks, development/production builds and ESLint. Crank rotation is checked for fixed scrollable bounds with pointer input in production as well as multiple visual angles. Detailed measurements remain in the ignored local diagnostic folder; browser diagnostics stay manually invoked.

The integration does not change simulation rules, scene ownership, world assets or save formats. Production dialogs retain their focus handling, input ownership, confirmation behavior and existing actions.
