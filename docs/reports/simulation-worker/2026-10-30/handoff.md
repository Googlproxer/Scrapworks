# Production handoff after lean publication

This is an implementation plan, not a runtime change. Retain the [29 October compatibility audit and migration order](../2026-10-29/compatibility.md), including the synchronous session/tick-hook changes, explicit failure/replacement and completed-tick rollback requirements. The lean laboratory adds the following obligations before production adoption.

1. Define production presentation fields and stable entity identities in plain contracts. The laboratory's ordinal/generation encoding is specific to its fixture. Keep all authoritative inventories, links, reservations and transactions in the worker; select compact render/HUD fields independently of component storage. Do not reconstruct 100,000 rich objects each render frame after receiving the numeric buffers.
2. Define asynchronous inventory/selection inspection in addition to the completed-view stream. Initial subscription results and subsequent nested updates must carry the current world generation, identity and tick. Unsubscribe on selection/panel/world changes. A replaced entity must invalidate old details and pending inspection requests. The laboratory caps concurrent detail subscriptions at 16 and qualifies the player plus one processor; verify the real UI's required subscription count before finalizing this cap.
3. Add a tested asynchronous port behind `GameRuntimeService` and `WorldSessionBridge`, starting with a compatible inline adapter. Initialization/readiness, current completed view, command results and inspection must be explicit. Preserve `Simulation`/`PlayerMotor` rules, move authoritative callbacks into plain systems and retain main-thread Toolkit hooks for input/presentation. Existing synchronous callers cannot assume an immediately advanced authoritative view.
4. Add one dedicated module worker and one private Miniplex runtime when production implementation is separately authorized. Keep one host-credit accumulator, one outstanding batch, 50 ms steps and the common five-step allowance. Preserve command ordering, suspension/input revision, no offline catch-up, failure settlement, generation guards, timeout and teardown. Retain complete versioned deltas; a gap needs resynchronization rather than dropping a delta. No second ticker, authoritative mirror, shared stores or worker pool is needed.
5. Bind `PlayerView` and other presentation readers to the latest completed typed cache and interpolate between authoritative movement views. A completed presentation cache is not a save/recovery snapshot. Keep full capture/rebuild on its own operation and schedule any large initialization/capture work explicitly; lean tick success does not remove that cost. Placement previews remain advisory and commands revalidate in authority.
6. Repeat actual Angular/Babylon scene qualification, including worker packaging/CSP/base URLs, movement/camera/animation feel, input ownership, pause/focus/Inspector transitions, replacement/Retry, accessibility, allocation and long sessions. The static-position processor benchmark and isolated packaging probe do not establish rendering or physical input-to-photon performance. Compare the integrated inline control under the same scene before claiming an overall worker improvement. Prediction remains deferred until evidence warrants it.

Retain only one authoritative backend at a time. A rollback selects a compatible inline backend at construction; changing a live backend needs a complete validated capture at a completed-tick barrier. There is no transparent mid-failure fallback and the renderer cache cannot recreate lost authority. The existing migration diagrams describe the implemented synchronous runtime and should change only when the corresponding production work lands.

The future Miniplex/bitECS threading assessment remains separate: compact transferable publication is available to both and does not require bitECS, SharedArrayBuffer or parallel ECS systems. Reopen additional simulation threading only if real simulation profiles justify it. No production dependency, runtime integration, gameplay system or multi-worker ECS is delivered by this report.
