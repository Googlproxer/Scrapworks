# Authored world compilation

`compile.ts` reads saved Editor JSON and publishes a version 1 plain `WorldDefinition` through the staged scene exporter. It does not instantiate Babylon or execute attached scripts. A malformed definition stops export before publication; scenes, generated script registry and `worlds/game.json` retain their last working generation together.

The active Game scene contains world/spawn/resource markers and six physics test markers. Edit their transforms and `metadata.scrapworks` fields in the Editor's saved source:

| Marker kind | Required metadata | Transform meaning |
| --- | --- | --- |
| `WorldSettings` | `version: 1`, stable `id`, `columns`, `rows`, `cellSizeCm`, `terrainId` | Minimum X/Z grid corner, ground elevation zero, no final rotation. |
| `PlayerSpawn` | `version: 1`, stable `id` | Player ground position. |
| `Deposit` | `version: 1`, stable `id`, `resource: "scrap"`, positive `quantity`, `footprint: {width, depth}` | Centre of the footprint's minimum X/Z cell; yaw in quarter turns. |
| `Blocker` | `version: 1`, stable `id`, `footprint: {width, depth}` | Same footprint anchor and rotation convention. |
| `PhysicsBody` | `version: 1`, stable `id`, `collision`, `motion: "dynamic"` or `"kinematic"`, positive `mass` in kg | Body centre in centimetres, including elevation; quarter-turn yaw. No grid footprint. |

Exactly one settings marker and one spawn are required. IDs must be unique; positions must be finite and inside the world; entity anchors must be cell-centred; footprints must fit without overlap. Parent translation and quarter-turn yaw compose before centimetres become metres. Marker hierarchies require unit scale and zero pitch/roll; unsupported transforms, missing parents and cycles fail explicitly. Visual geometry and mesh bounds never determine occupancy.

Movement collision is separate from placement occupancy. `Deposit` and `Blocker` metadata may include `collision: {shape: "box", width: 150, height: 150, depth: 150}` or `collision: {shape: "cylinder", radius: 25, height: 170}`. All marker dimensions are centimetres; export converts them to metres. Shapes stand on the ground at the footprint centre and rotate with its quarter-turn yaw. Dimensions must be finite and positive, and horizontal bounds must fit inside the reserved footprint. Omitted collision metadata uses a box covering the full footprint, 1.2 m tall, matching the developer test building.

The current blocker uses a 150 cm box; the capsule standing in for scrap uses a 25 cm radius, 170 cm tall cylinder. Rapier 0.21.0 resolves movement with a 0.35 m radius, 1.7 m tall player capsule and its maintained character controller. The 2 mm contact margin is separate from the radius. An infinite ground plane avoids box-floor shape-cast noise; static walls enforce map limits and water remains blocked. Placement still reserves whole cells. Depleted deposits release their native collider. The former custom overlap/sweep solver has been removed; `world-collision.ts` now only converts authored primitive descriptions.

## Physics ownership and continuation

`Simulation` owns one `WorldPhysics` instance in its existing dedicated worker. Rapier's compat package embeds the WASM payload and is pinned exactly; it adds no CDN fetch, secondary worker, cross-origin-isolation requirement, ticker, or Babylon dependency to simulation. Module initialization is asynchronous, so the worker installs its native message listener before dynamically loading the runtime. Initialization failures reach the normal native worker error/Retry boundary. After readiness, requests and fixed steps remain synchronous and ordered.

Each 50 ms gameplay step performs three 1/60 s physics substeps. Gameplay commands are still applied once per owning tick, and host catch-up/in-flight work still share five credits. Physical ECS components own stable IDs and definitions; native bodies are reconciled at structural boundaries. Ground-item churn does not rebuild collision. Active bodies and the previous active set supply changed poses, including a body's final sleeping pose.

Authored movers use native velocity-based kinematics, targeting the next point of their tick-driven path each substep. Rapier's character controller applies platform friction to nearby side contacts too, so the worker adapter uses native contact normals to limit carrying to walkable support. Side contacts can push when the surface reaches the capsule, but cannot pull the player back or carry them sideways. Support motion enters the character's requested movement once, maintaining the controller's contact margin. The adapter exposes only the applicable normal velocity during the synchronous character query and restores full native velocities before stepping dynamics. Rapier still owns contact geometry, shape casts, sliding and dynamic-body impulses; there is no renderer collision authority or replacement solver.

Presentation keeps its eight-number entity rows and adds a separate transferred six-number slot/generation/quaternion stream only for changed physical bodies. Native handles never enter presentation. Babylon interpolates completed positions and quaternions and owns meshes, materials and debug attachments. Missing publications, resynchronization and renderer replacement use the full current view. The production graph check rejects Rapier and physics authority in the main graph.

World captures are version 3 and require format-3 Rapier state: engine/version, native bytes, stable IDs in native iteration order, and the player's vertical velocity. Format 3 separates authored static entity IDs (`solid:entity:`) from generated terrain IDs (`solid:terrain:`), retaining velocity-based movers. Earlier native formats are rejected. IDs reconstruct private native mappings without persisting exposed body handles. Restore validates engine version, world gravity/timestep, floor/boundaries, collider geometry/configuration, body motion/mass, physical poses and ECS identity in a separate candidate before replacing a live world. Earlier internal capture formats are rejected; this is capture/rebuild infrastructure, not Milestone 4 gameplay storage. Edited test initial conditions use the explicit `tools/testing/rebuild-physics.ts` helper, never a production compatibility fallback. A native snapshot is tied to the pinned engine version and will need an explicit migration strategy if that dependency changes.

The current M8 map has a 20 by 20 grid, 200 cm cells and minimum corner (-1000, 0, -1000) cm. WorldSettings.terrainCells supplies explicit validated column/row/terrain overrides: a connected 4 by 2 lake occupies columns 12–15, rows 6–7 (zero based). Deposit.kind accepts scrap or coal. The original opening markers remain in place; two additional 250,000-scrap markers and one 250,000-coal marker provide expansion resources. Spawn is (100, 0, 100), scrap is (-300, 0, 100), and the blocker is (300, 0, -100). All other terrain starts as soil; environmental health is mutable simulation state and starts at zero. World views use metres with X east, Z north and Y up. The neutral character anchor uses scale one; the character adapter owns the one-time model conversion.

`GameSession` advances the plain simulation at 20 Hz, limits catch-up to five steps per rendered frame and clears timing/input on suspension. Walk speed is 1.5 m/s, sprint 3 m/s, player collision radius 0.35 m, and placement reach 3 m from the player's position to the anchor-cell centre. The test building is two cells by one, rotated in quarter turns. Its free availability exists only in an explicit developer fixture session; normal worlds start without inventory, equipment, research or buildings.

Character presentation turns by the shortest angle at 900 degrees per second, taking 0.1 s for a quarter turn and 0.2 s for a reversal. This rate applies while moving and after releasing a movement tap; animation blending and pause behavior remain independent.
